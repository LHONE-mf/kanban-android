## Проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
for test in tests/test_*.js; do node "$test"; done
python3 tools/build_kanban_js.py --check
node --check app/src/main/assets/kanban.js
node benchmarks/comrade-performance.js --check
git diff --check
```

17 Python-проверок и 40 JS-сценариев, включая новые проверки записи и плеера, фото, галереи, Pomodoro, напоминаний, ZIP и автономной миграции. GitHub Actions также выполнил `gradle :app:compileDebugKotlin --no-daemon`, `gradle :app:assembleDebug --no-daemon`, сверку подписи и версии. Первый эмуляторный smoke в GitHub Actions не начал Maestro. У раннера не было аппаратного ускорения, а новая версия эмулятора требовала явного включения TCG. Workflow обновлён и запустил сценарий с точными APK 1053 и 1085. [CI APK](https://github.com/LHONE-mf/kanban-android/actions/runs/45702517213) · [Регрессии на коммите отчёта, CI №1089](https://github.com/LHONE-mf/kanban-android/actions/runs/45706050966) · [Первый запуск эмулятора](https://github.com/LHONE-mf/kanban-android/actions/runs/45700087689) · [Проверка обновления](https://github.com/LHONE-mf/kanban-android/actions/runs/45703920958)

После включения TCG GitHub Actions установил исходную APK 1053. Сценарий остановился при подготовке тестовых данных из-за разрыва соединения с WebView. На локальном Android 35 (x86_64, TCG) исходная APK тоже установилась. Логи зафиксировали сбой процесса рендеринга WebView до создания снимка IndexedDB. Отдельная проверка `adb install -r` прошла с APK 1053 на 1085. До и после установки совпали UID приложения и содержимое тестового файла, созданного через `run-as` в `files/`. Это подтверждает обновление пакета и сохранение приватной папки. Проверку содержимого IndexedDB на эмуляторе завершить не удалось.

На Linux проверочный перенос импортирует тестовый ZIP в отдельную SQLite и сверяет строки задач и досок, внешние ключи, SHA‑256 файлов и целостность базы. Тесты моделируют обрыв после подготовки байтов, повтор, битый хэш, недопустимый путь и ссылку на отсутствующий результат. На Android тестовый APK проверяет ту же схему и нативное файловое хранилище из кода приложения. Команда запуска после установки обоих APK:

```sh
adb shell am instrument -w -r com.kanban.offline.test/com.kanban.offline.KanbanStorageInstrument
```

На Android 35 (x86_64, TCG) подписанная APK №1101 и тестовая APK установились через `adb install -r`. Инструментация завершилась с `INSTRUMENTATION_CODE: -1`. Прошли восстановление SQLite-снимка после ошибки подготовки, восстановление опубликованного с обрывом голосового черновика, чтение ZIP после экспорта, отклонение вложения с неверным SHA‑256 и проверки фото. В Linux Chromium отдельный профиль подтвердил реальный откат транзакции IndexedDB при пропущенном фрагменте ZIP и успешное сохранение точных байтов при повторе. [Тестовая APK для инструментации](https://github.com/LHONE-mf/kanban-android/actions/runs/45757738576/artifacts/15088047962)

В рабочем приложении снимок создаётся по подтверждению пользователя, а чтение и редактирование продолжают работать через IndexedDB. Для переключения нужны пакетные чтение и запись в SQLite, сверка данных до и после обновления APK и отдельные испытания на прерывании процесса и нехватке места через реальный путь WebView. Физических устройств в среде нет. [Описание переноса](P19_STORAGE_MIGRATION.md) · [Ручная проверка](P19_ANDROID_ACCEPTANCE.md)

## Производительность

Бенчмарк P17 выполнялся на Node v24.22.3, Linux x64. Исходный код `a0f1268` и P19 на этапе сборки №1085 измерены на одной машине попеременно, по три полных запуска на версию. В каждой ячейке медиана трёх серий из семи измерений, мс на операцию. p95 показан аналогично.

| Операция | Задач | Медиана исходная → P19 | p95 исходный → P19 |
| --- | ---: | ---: | ---: |
| Каркас доски | 100 | 0,264 → 0,262 | 0,434 → 0,309 |
| Каркас доски | 1 000 | 1,075 → 1,033 | 1,918 → 1,993 |
| Каркас доски | 3 000 | 3,446 → 4,327 | 6,006 → 5,232 |
| Текстовый поиск | 3 000 | 1,290 → 1,385 | 1,693 → 2,326 |
| Фильтр по приоритету и сроку | 3 000 | 0,979 → 1,019 | 1,040 → 1,042 |
| Выбор места сброса | 3 000 | 0,001 → 0,002 | 0,002 → 0,002 |

На 3 000 задач медиана каркаса выросла на 0,881 мс, а p95 снизился на 0,774 мс. Этот стенд исполняет одинаковые функции построения каркаса и поиска в обеих версиях. Замер чувствителен к нагрузке среды. Для расчёта задержки экрана требуется Android/WebView.

Размер APK вырос с 6 328 804 (№1053) до 6 529 276 байт (№1101), на 200 472 байта (3,2%). Метрики холодного запуска, сохранения карточки, обработки фото, воспроизведения, большого ZIP, пикового потребления памяти и места на диске на физическом Android остаются открытыми.
